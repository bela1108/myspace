# Python 后端安全项目题集

100 道题，基于 20 个项目的固定提交。困难 59 道，地狱 41 道。

题目覆盖防御性检查、数字取证、供应链审核与安全治理。验收以题面指定的本地小样本为主，使用项目既有依赖，无需 Docker、联网服务或生产数据。

## 基线验证

先打开对应项目的起始快照，取得该提交的源码。在项目根目录用 Python 3.12 创建并激活虚拟环境，然后按项目小节安装依赖、运行选定基线。

```sh
python3.12 -m venv .venv
. .venv/bin/activate
export PYTEST_DISABLE_PLUGIN_AUTOLOAD=1
```

基线耗时为本机运行记录，依赖安装时间单独计算。

### 001 发布包拆成两层后别把审计入口一起裁掉

困难 · 漏洞利用与缓解 · 功能开发

项目把安全规则分成默认依赖和现场选装包，构建中心要能在只导入已声明插件的情况下核对一套扫描配置是否真的能启动。请给 Bandit 增加打包预检，从离线 entry point 清单、依赖声明和配置启用项做三方闭合，处理本地与第三方插件重名、同包不同发行版及安装后才可探测的能力。禁止临时加载候选插件执行探测。用两份合成包元数据证明同一配置在完整分发件可用、在仅裁掉一个非默认依赖时应显示精确的失效范围和替代安全配置。

### 002 谁还可能拿到日志回调交出的未授权数据

地狱 · 漏洞利用与缓解 · 功能开发

内部报表的写入函数接受回调，库有时在事务提交时调用，有时等一次手工重试才调用。请让 Bandit 支持以可声明的生命周期合同分析该类接口，追查闭包、部分应用和工厂返回的回调捕获了何种敏感对象，结合实际可见字段和回调时段区分确定泄露、未知和许可。用假工单对象覆盖回调移入外部容器、已净化对象仍可复用及一次失效回调保证没有执行，诊断要明确指到注册处与执行合同。

### 003 只设置了其中一个安全响应头

困难 · 漏洞利用与缓解 · 功能开发

代码库里有一批返回员工报表的 handler，团队靠装饰器给响应加安全头，个别提前返回由另一层传出。请把响应头合同做成 Bandit 的可配置静态规则，能跟踪响应别名、包装器的有限摘要、字典覆写和不同提前返回。允许用户声明哪个封装保证哪些头，循环或外部响应对象无证据时保留未知。测试要有两个包装层，其中内层标了完整头，只有经外层创建新响应的那个出口报缺项并显示改写点。

### 004 常驻任务把过期的特权租约留给下个消费者

地狱 · 漏洞利用与缓解 · 功能开发

我们有个内部批任务用异步上下文临时拿到提升权限的客户端，代码评审想知道对象会不会被存进长寿命队列。把项目显式配置的租约获取、受管借用、转交及注销纳入 Bandit 静态检查，分开表示泄出租约、清理未保证和需要人工看三种结果。闭包捕获和异常重抛必须一起考虑，主动延长有效期的受信 API 要有独立规则。用模拟客户端断言借用结束后调用与闭包永不执行在报告里得到不同判定。

### 005 审查自动修正会不会擦除同文件的别项安全审核

困难 · 漏洞利用与缓解 · 质量保障

编辑器根据 Bandit 诊断给文件提交一批修正，安全组要先确定这些编辑能共同应用，且没有顺便吞掉另一诊断对应的人工审批。请用现有 Bandit 报告接一个离线修正审查入口，按原文件身份与字符位置映射编辑前后告警和人工标注，处理交叠编辑、相邻插入及注释关联变化，先决条件不齐时保留原因。测试用完全无害的 Python 源码和自定义站位规则，某两条编辑单独通过但合起来应被阻止，第三条无关的安全修正仍可采用。

### 007 外包暴露面核算的区间与确认预算

地狱 · 安全风控与治理策略 · 功能开发

共享位置清单已经脱敏，部分秘密报告只知道属于两个候选发布件之一。现在要用 detect-secrets 的结果建立离线风险核算，按照调查证据排除不可能归属，计算每件和全局的暴露计数上下界，并给出在一次核查名额下最能缩小区间的待核问题。相同哈希的独立发现与同一发现的多个位置要分开建模。四个假候选中安排两条互斥归属，报告必须证明逐件上界之和可以大于全局上界。

### 008 阻止证据过滤器误吃掉应保全的候选

困难 · 多方向混合 · 功能开发

资料清理流程允许注释屏蔽测试凭据，不过一旦取证保全名单命中文件，就得留下一条不含原文的复核记录。请把该选择接入 detect-secrets 扫描与报告，保全决策依据文件稳定版本及命中区间，注释、词表等过滤器仍应留下各自结论以便复查；对未扫描和已过滤分别报告。用两份内容相近的虚构文件和一次改名验证，仅同一版本的命中延续保全，而且现有扫描入口不泄露原始占位符。

### 009 在联签额度里扣掉真实复检消耗

困难 · 安全风控与治理策略 · 功能开发

内部安全和法务共用同一批应急复检名额，候选需先确认各方同意，取消也可能发生在某些复检已经执行以后。用 detect-secrets 的脱敏候选作为工作项，支持离线核对预约占额、真实复检扣账、无效意见和补偿记录，对同时出现的两个有争议预约给出确切缺少的同意。验收跨两个重叠案件分别导出当前剩余额度和原结算凭据，导入重复回执不二次扣账。

### 010 扫描留存窗口与原件销毁执行能否对证

地狱 · 顺带涉及上下游链路 · 功能开发

监管要求扫描系统保留处置依据，但一部分原件按合同必须较早销毁。把现有 audit 结果接入本地交接核对，比较扫描时点、证据冻结、加封和各副本销毁回执，既能解释某份报告依据哪场保全，也能指出只有销毁承诺尚缺实证的副本。离线输入只放假的内容摘要和副本编号，覆盖保全延展通知迟到和销毁时钟不一致；历史报告允许重算，当前输出不得凭晚到通知改写过去。

客户要在一批加密 Office 证物到期前完成核查。有的格式可只核外壳，部分档案必须把单独的封存回执交给指定保管员。请围绕库的离线格式证据信息做核查排程，从本地职责清单、附件可用期和允许运行的检查种类推导最小可行移交，多个条件冲突时给出需延期的位置。交给保管员一份可按虚拟时钟重放的计划和卡住的延期理由，全程只观察无宏示例的保护外层。

### 100 入库观察和正式鉴定需要在附件沉底后仍能对证

困难 · 数字取证 · 功能开发

Office 案件的原件入库时只生成非敏感格式观察，要到第二天才由保全人复核受保护内容有没有取得处理许可。请给 msoffcrypto-tool 做只读鉴定回执，从合法样品的初始格式结论、可复验的公开性质和事后更正建立可中断的审理记录，确保接受某项更正无法抹掉其他待核观察；对旧案件兼容已有格式识别。验收在鉴定写出一半终止后重跑，显示已经确认的格式结论只能续签一次，未确认材料依旧待查。
