### 001 邮件链接的关闭世界时间线

地狱 · 数字取证

调查员从同一封邮件的两份拷贝提取链接，一份经过 Safe Links 重写，另一份是用户保存的原始地址。请让 Unfurl 离线标出包装层时间与实际目标自身携带的时间，原始地址重合时也保留各自的观察来源和时区置信度。验收时并排展示原址快照、重写时间和仍未知的点击时间，第三层包装即使重复引用也不合并证词。。

### 002 证据图的受限分享

困难 · 数字取证

邮件调查的 Unfurl 图需要发给另一组，但邮箱和 URL 里的个人标识不得离开案件。为图导出增加案件内一致、案件间隔离的符号替换，保留公开域名和边的来源，处理一个值同时作为父节点原文和后代解析结果的情况。取两份含同一邮箱的案件，导出后组内仍能连图，两个案件的替代值对不上。

### 003 静态链接解析器的来源仲裁

地狱 · 数字取证

安全团队现在把浏览器历史里一条字符串交给好几个 Unfurl 解析器，多个结果可能给出同名字段但依据完全不同。让值、解释路径和父节点标识可以共同进入复核队列，复核接受一个分支后旧的观察仍可检索。构造两个离线解析器先后互换的夹具，人工确认的分支应由内容决定，也能逐级返回原始输入。

### 004 取证链接图的纠错传播

地狱 · 数字取证

同一个邮件链接被送检两次，人工后来纠正了其中一次的目标，平台仍在使用从旧目标派生的域名观察。新增离线纠错记录，撤回沿依赖边传播，仍有独立来源的观察继续有效。交一张五节点图作验收，提交两次相同纠错不会撤销后来确认的另一条边。

### 005 云端下载链接的文件归属线索

困难 · 数字取证

同一个疑似外发文件在浏览历史里出现了直链和带展示名的分享页。整理 Dropbox 分支输出，让证据报告能把明确的服务端标识、用户可见名和采集来源并排提供，给有歧义的重名文件留待人工确认。全部用占位标识，本地夹具里的两个同名对象应形成两个待复核条目。

### 196 SBOM 抽检对象的证词验证

困难 · 安全风控与治理策略

供应商的清单里有很多重复观察，人工审核只能抽查几项，外采组件却要求强制覆盖。请用 CycloneDX 模型生成可解释的抽样方案，证据缺少的组件先待补证，记录为什么无法覆盖。小 BOM 中增加同一来源的重复观察，抽检权重不应被那条重复观察抬高。

### 197 受控 SBOM 披露后的依赖闭包

地狱 · 安全风控与治理策略

客户只可看获批的 CycloneDX 组件集，导出时若删除中间节点，原来依赖关系的证据也要妥当处理。实现服务端可审查的披露计划，保留统计与引用一致，给定空白区间时不捏造替代依赖。五个虚构的组件形成一个小依赖图，获批披露的一侧能验证自己看到的范围，也能判断证据在哪个依赖节点被截断。。

### 198 处理状态的双系统交接

困难 · 顺带涉及上下游链路

供应商发来的 SBOM 已写了处置符号，接收方还要根据自己运行环境进行关闭或继续审查。把供应商判断与内部评估作为可比较两套记录，能保留对应产品、版本和理由，老调用还可以独立读取供应商材料。一张小型对照表即可验收，当运营方改变自己的处置说明时，供应商当日提交的判断仍可独立复核。。

### 199 发布清单中组件换代的验收

困难 · 安全风控与治理策略

软件清单先在试产阶段生成，发版时组件版本和组成会小幅变化，审批想核实哪些试产授权还适用。增加可追溯阶段对照，两个真实组件被识别为同一依赖时仍要区分其发生阶段。小 BOM 的验收里一项只换阶段、另一项确实换内容，报告需分别解释。

### 200 风险声明的复核凭证按生命周期合并

地狱 · 安全风控与治理策略

安全清单里采购时的复核声明不能替代已上线资产的签收。给 CycloneDX 的离线校验侧补阶段级依赖证明，撤回采购证词时仅重开显式依赖它的决定，生产阶段的实测证词仍有效。三个小 BOM 包含一个共用组件及不同阶段声明，能追出每项复核从何而来。
