# DUO139

This linter searches for digests passed to a purpose they are not
permitted for. Digests are classified by the function that produced
them: for example, an archive digest may be used for integrity checks,
while external deduplication requires a recipient-facing digest.

The linter is driven entirely by configuration:

* `digest_sources` maps a digest-producing function name to the kind of
  digest it returns, e.g. `{"archive_digest": "archive"}`.
* `entry_points` maps a checked function name to a mapping of parameter
  (positional index or keyword name) to the purpose that parameter
  serves, e.g. `{"publish": {0: "integrity", 1: "external"}}`.
* `usage_policy` maps a purpose to the digest kinds permitted for it.

Within a function the linter tracks assignments, tuple unpacking, simple
conditional merges, and direct-return helper functions. A proven misuse
is reported at the offending argument. Arguments whose provenance cannot
be determined (e.g. produced by an unknown call) are reported as
uncertain rather than assumed compliant.

## Problematic code

```python
digest = archive_digest()
publish(archive_digest(), digest)  # archive digest used for external dedup
```

## Correct code

```python
digest = recipient_digest()
publish(archive_digest(), digest)
```

## Rationale

Sending a digest to a purpose it was not created for can leak
information or silently defeat the mechanism the digest protects.
Archive digests are suitable for integrity checks, but external
deduplication must only use recipient-facing digests.
