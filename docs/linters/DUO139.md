# DUO139

This linter looks for validation APIs whose asynchronous result is confused
with a completed security check. It is deliberately scoped: no API is
considered a validator unless the caller declares it.

## Declaring validation APIs

Use the `--dlint-validation-api` flake8 option, repeated or
comma-separated:

```
python -m flake8 --dlint-validation-api=internal.security.verify \
    --dlint-validation-api=internal.security.verify_signature .
```

Programmatic users can pass `validation_apis` to the linter:

```python
linter = BadAsyncValidationUseLinter(
    validation_apis=["internal.security.verify"],
)
```

The class attribute `validation_apis` and the aliases `guard_apis` and
`check_apis` are also accepted.

## Misuse: missing await

A locally defined `async def` proves that the call produces a coroutine. Using
that object directly as a condition is always truthy and does not run the
validation:

```python
async def verify_payload(payload):
    return payload == "trusted"

def handle(payload):
    if verify_payload(payload):  # DUO139 missing await
        return "allowed"
```

## Misuse: awaited result discarded

Awaiting a declared validator is not enough. The result must control a
statement, assertion, return relation, or another proof path:

```python
async def handle(payload):
    await verify_payload(payload)  # DUO139 awaited result is unused
    return "allowed"
```

## Correct use

```python
async def handle(payload):
    if await verify_payload(payload):
        return "allowed"
    return "denied"
```

Simple assignment is followed as well:

```python
allowed = await verify_payload(payload)
if allowed:
    return "allowed"
```

## Uncertainty

The linter reports "needs confirmation" instead of a definite failure when:

* The declared API has no local definition. Its return may be synchronous,
  asynchronous, or raise on failure.
* Branches assign a checked value on one path and a coroutine or an unchecked
  value on another.
* A validation result is handed to an external function, so the linter cannot
  prove how it is consumed.

A plain `await` is not treated as a security check by itself. Only values
derived from declared validation APIs, or local wrappers whose return relation
can be followed back to one of those APIs, are considered.

## Limitations

This is intentionally a local, limited analysis. It does not inspect installed
packages, model arbitrary mutations, or perform full path-sensitive analysis.
Use the "needs confirmation" results as review prompts rather than automatic
fix-ups.
