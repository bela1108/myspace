# DUO140

This linter classifies each in-file consumer of an internal data-export
generator by the consumption stage it guarantees and reports when the
ending audit cannot be confirmed.

Consumption stages:

* first consumption (`next(g)`, `iter(g)`, single conditional use)
* early break (a `for` loop whose body contains a `break` statement)
* explicit close (`g.close()`)
* full exhaustion (`list(g)`, `sum(g)`, a `for` loop without `break`, etc.)

## Problematic code

```python
def export_rows():
    audit_start()
    for row in database.cursor():
        yield row
    audit_end()

def consume():
    for row in export_rows():
        if row.id == target:
            break
```

The `break` can stop iteration before the generator reaches its final
`audit_end()` line, so the ending audit is never confirmed.

## Correct code

```python
def export_rows():
    try:
        audit_start()
        for row in database.cursor():
            yield row
    finally:
        audit_end()
```

## Rationale

An ending audit written at the bottom of a generator only runs while the
generator is consumed. Handing the generator to another consumer, breaking
out early, or closing it explicitly does not guarantee that line is
reached. When the consumer contract cannot be determined from the file,
the linter emits a review diagnostic instead of guessing.

## Exceptions

Only generators and one layer of in-file wrapper functions are analyzed.
Consumers imported from another module require manual review.
